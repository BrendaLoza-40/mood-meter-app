# Supabase Table Reference Guide

This guide shows you exactly what the `moods` table looks like and what data goes into each column.

## Table Structure

The `moods` table has these columns:

| Column Name | Data Type | Description | Example Value |
|------------|-----------|-------------|---------------|
| `id` | BIGSERIAL | Auto-generated unique ID (you don't fill this) | `1`, `2`, `3` |
| `timestamp` | TEXT | Full date and time when mood was selected | `"2025-01-15T14:30:00.000Z"` |
| `date_only` | TEXT | Just the date (YYYY-MM-DD) | `"2025-01-15"` |
| `l1_id` | TEXT | Level 1 emotion ID (quadrant) | `"high-pleasant"` |
| `l1_label` | TEXT | Level 1 emotion label (human-readable) | `"High energy pleasant"` |
| `l2_id` | TEXT | Level 2 emotion ID (specific emotion) | `"high-pleasant_l2_1"` |
| `l2_label` | TEXT | Level 2 emotion label (human-readable) | `"Joyful"` |
| `time_to_select_ms` | INTEGER | Time taken to select mood (milliseconds) | `3500` |
| `created_at` | TIMESTAMPTZ | Auto-generated timestamp (you don't fill this) | `2025-01-15 14:30:00+00` |

## What Data Goes Where

### When a user selects a mood, here's what gets saved:

**Example: User selects "Joyful" from the "High energy pleasant" quadrant**

| Column | Value | Where it comes from |
|--------|-------|---------------------|
| `id` | `1` | Auto-generated by database |
| `timestamp` | `"2025-01-15T14:30:00.000Z"` | Current time when user clicked |
| `date_only` | `"2025-01-15"` | Just the date part of timestamp |
| `l1_id` | `"high-pleasant"` | The quadrant ID user selected |
| `l1_label` | `"High energy pleasant"` | Human-readable quadrant name |
| `l2_id` | `"high-pleasant_l2_1"` | The specific emotion ID |
| `l2_label` | `"Joyful"` | The specific emotion name |
| `time_to_select_ms` | `3500` | How long (in milliseconds) it took user to select |
| `created_at` | `2025-01-15 14:30:00+00` | Auto-generated by database |

## SQL Script to Create Table

When you paste this into Supabase SQL Editor, it creates the table structure:

```sql
-- Create moods table
CREATE TABLE IF NOT EXISTS moods (
  id BIGSERIAL PRIMARY KEY,
  timestamp TEXT NOT NULL,
  date_only TEXT NOT NULL,
  l1_id TEXT NOT NULL,
  l1_label TEXT NOT NULL,
  l2_id TEXT NOT NULL,
  l2_label TEXT NOT NULL,
  time_to_select_ms INTEGER NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Create indexes for faster queries
CREATE INDEX IF NOT EXISTS idx_moods_date_only ON moods(date_only);
CREATE INDEX IF NOT EXISTS idx_moods_timestamp ON moods(timestamp DESC);

-- Enable Row Level Security
ALTER TABLE moods ENABLE ROW LEVEL SECURITY;

-- Create policy to allow operations
CREATE POLICY "Allow all operations for service role" ON moods
  FOR ALL
  USING (true)
  WITH CHECK (true);
```

```

    ↓
App sends to Server:
{
  "timestamp": "2025-01-15T14:30:00.000Z",
  "dateOnly": "2025-01-15",
  "l1": { "id": "high-pleasant", "label": "High energy pleasant" },
  "l2": { "id": "high-pleasant_l2_1", "label": "Joyful" },
  "timeToSelectMs": 3500

    ↓
Server transforms and saves to Supabase:
{
  timestamp: "2025-01-15T14:30:00.000Z",
  date_only: "2025-01-15",
  l1_id: "high-pleasant",
  l1_label: "High energy pleasant",
  l2_id: "high-pleasant_l2_1",

  time_to_select_ms: 3500
}
    ↓
Appears in Supabase Table Editor
```

## Quick Reference

- **Auto-filled columns**: `id`, `created_at` (you don't need to set these)
- **Required columns**: All others must have values
- **Text columns**: Use quotes in SQL: `'high-pleasant'`
- **Integer columns**: No quotes: `3500`
- **Timestamp format**: ISO 8601 format: `"2025-01-15T14:30:00.000Z"`

---

**Tip**: You don't need to manually insert data - the app does it automatically! This guide is just for understanding what's stored.
